# NTVV full upgrade: step-by-step delivery plan

This is the project plan for the farm game, separate from the older stability audit. The first upgrade increment merged into `master` through [PR #1](https://github.com/quyenanh198/ntvv/pull/1) on 2026-10-12. The acceptance gates below remain the plan for staged deployment and subsequent iterations. The existing gameplay spec describes current rules, not a locked design for this upgrade.

## 1. Establish the player baseline

- Capture the current farm at 320, 390, 768, and desktop widths; record the first 10 minutes and a returning-player session.
- Gather player feedback or analytics for first crop planted, first harvest, first sale, day-2 return, and errors. If none exist, run 5 observed play sessions before final balance decisions.
- Deliver a one-page product brief: audience, core feeling, session lengths, and three measurable goals. The [working brief](product-brief.md) now defines provisional targets and the [five-session script](player-session-script.md) defines how to observe the first and returning visits.
- **Gate:** the team can name the top three points where players stop or become confused. **Status:** the server now records first plant, harvest, direct sale or order delivery, and 24–48 hour return for new farmers and exposes aggregate ten-minute and day-two counts through a protected endpoint. These measurements begin only after deployment; external player evidence and five observed sessions remain pending. Code inspection and local browser walkthroughs are complete.

## 2. Define the visual language and asset inventory

- Set a shared camera angle, outline weight, lighting direction, palette, shadow, and sprite scale. Draw a reference farm scene. The working standard and inventory are in [art-direction.md](art-direction.md).
- Inventory every crop growth state, tree, animal, building, machine, product, UI icon, and background; label missing assets and inconsistent styles.
- Set export rules: transparent PNG/WebP, predictable names, size variants, and a source file for every new sprite.
- **Gate:** a single screen using the new art feels coherent at phone and desktop sizes. **Status:** farmhouse, red barn, greenhouse, coop, windmill, market, fishing pond, farmer, shared hand-painted seedling, all thirty-six matched crop pairs, individual art for all fifteen animal species, thirteen fruit-tree species and their fruit items, and all twelve factory machine sprites added to a working art guide and generated catalog/static-asset inventory; the reference farm scene and painted scarecrow are now in the repo. All fifteen animal products and all eight premium-workshop products have individual PNG or SVG icons; all 186 catalog products now have PNG or SVG icons; the owned decoration gallery and shop now share painted previews for all 22 catalog decorations; all seven catalog pets now have painted previews (six new sprites and the existing rabbit); interface art and style consistency remain pending.

## 3. Upgrade the farm scene and graphics

- Replace remaining mixed emoji/SVG gameplay art in batches: starter crops and growth states, trees, animals, machines, then decorations.
- Add readable soil states, planting/watering/harvest feedback, object depth, and restrained ambient motion. Honor reduced-motion settings.
- Test sprite clarity and tap targets at 320px; keep downloads small through resizing and compression.
- **Gate:** a player can distinguish empty, growing, dry, and ready plots without reading labels. **Status:** four plot states now have distinct soil and border treatments, and a 320px browser check confirms they render together with accessible action names; observed-player validation and other asset families remain pending.

## 4. Rebuild the first session

- Guide one plot through seed choice, planting, watering, harvest, inventory, and first sale. Make every prompt lead to the right action.
- Reveal new systems only when unlocked. Put accessible next actions above the plots on phones.
- Test with a fresh account, a returning low-level account, and an interrupted session.
- **Gate:** five new players complete the first sale without help; no starter can be blocked by tax or unaffordable seed. **Status:** guided path implemented; CI drives a fresh player through seed selection, planting, watering, ready-state harvest, inventory, and first sale at 320px, checking that the sale leaves more gold than the starter balance. The browser closes and reopens after watering to verify the crop persists, then returns after the sale to verify gold and the empty plot persist. Growing and ready screenshots were reviewed. The five-player observed gate remains pending.

## 5. Make everyday play easy to read

- Show the next three unlock levels and the current short-term goal. Simplify seed and inventory choices so usable items appear first.
- Review crop timings, waiting periods, orders, animals, and processing queues as one daily play loop.
- Make ready states, costs, rewards, and failure reasons clear before an action is committed.
- **Gate:** a returning player can find a productive action within 10 seconds. **Status:** upcoming unlocks and early seed choice shipped on branch; the farm-first responsive layout now puts next action and plots before family search on phones and gives the family a separate desktop sidebar. When an order is ready, the next-action prompt opens that sheet instead of suggesting empty plots. The order sheet puts deliverable orders first and names each requested product, held quantity, missing count, and reward. Regular orders now offer a direct seed choice for a missing crop or a factory shortcut that highlights the missing processed product recipe. The farm next-action prompt now also directs returning players to completed factory batches and hungry animals, with browser checks that open the factory collection and feed purchase controls. Shop feed, gem, and dog-hire buttons now show exact costs without hover; animal purchase availability checks both gold and pen space, with species-specific counts. Skill cards now show explicit ranks, next-rank costs and point shortages with a Can learn filter and respec reasons. Daily quests now have activity shortcuts, accessible progress cards, and clear chest states; tasks finished after opening the chest also pay once when completed, with retry/restart coverage. The barn overview has counted owned/hungry filters, feed needs per barn, and a direct pond shortcut. Barns now show hunger and shared feed stock, per-cycle product details, affordable bulk-purchase quantities, and a direct feed-shop shortcut with missing quantities. Fishing now shows the server regeneration interval, available casts, time to the next affordable cast, and the actual capped energy-purchase amount with gem/cap explanations. The pond now separates capacity and ready-batch summaries from stocking, places ready batches first, and shows the selected species sprite, seed price, grow time, and sale value outside the compact selector. The factory has All, Can make, and In progress views with counts and empty-state guidance so players can narrow the long recipe catalog. Inventory now has counted source categories and accent-tolerant search that combine to find stocked items without disturbing sale controls. Once the entire field is planted and no immediate work is ready, it shows the next crop countdown and opens that plot; a browser check covers the full-field case. Lottery ticket options now show exact total costs, remaining balances or shortfalls, and daily-limit guidance before purchase. Mobile coverage verifies insufficient funds, exact debit, and reaching the cap; concurrent API checks verify only one competing purchase spends a single available balance or final daily slot. Land expansion now previews resulting plot count, exact cost, level and gold shortfalls, remaining cash, starter tax immunity, and projected daily tax. A mobile walkthrough verifies blocked and affordable states, then purchases four plots with the exact debit and usable new land checked. Layout direction and measured checks are in [layout-direction.md](layout-direction.md); timing and player validation pending.

## 6. Rebalance progression and economy

- Model each level's expected play time, gold earned, seed cost, expansion price, and unlock value in a spreadsheet or script.
- Set separate early, mid, and late game targets. Check profitable loops, dead ends, runaway currency, and pay-to-skip pressure.
- Tune server constants, then run simulations and observed play sessions. Document every changed number and its reason.
- **Gate:** no common action leaves a player unable to continue, and level pacing matches the product brief. **Status:** starter tax deadlock fixed; the [balance report](balance-report.md) models all regular crops, visit cadence, expansion prices and land tax across all 97 expansions, opportunity margins across all 137 machine recipes, feed-adjusted sale income for all 15 animals, and sampled order premiums. No modeled expansion loses gold from its four new plots at one or three visits per day, but crop-only payback reaches 138 days for the final expansion. All sellable recipes have positive opportunity margin; direct and recursive crop-origin supply models cap recipe output by twelve plots and shared machine time at three visits per day. A new mixed-source scenario covers 86 direct recipes using crop, tree, animal, and farmed-fish ingredients with shared plot, pond, animal, and machine capacity. The animal model now reflects automatic production across elapsed cycles, exposing purchase payback measured in hours under sufficient-feed assumptions. These high possible margins need comparison with observed play before tuning. Sampled regular orders pay roughly 17–18% above direct sale value; in a no-stock starter-plot scenario only 18.3% of level-40 regular offers can be grown fresh before the two-hour board refresh. Slot 0 now guarantees a fast crop order each board, so players always have a fresh-field option under those assumptions. A 320px CI browser walkthrough plants the requested crop, harvests it, delivers that order, and verifies the inventory and gold changes; actual player completion rate remains unknown. The report also exposes an outdated daily-income target in the gameplay spec. Player measurement and tuning remain pending.

- **Measurement added:** a protected, persistent 30-day daily sales aggregate now separates direct sales by item family and order rewards. It begins collecting after deployment and will help test the animal and mixed-recipe scenarios against real player sales without exposing player IDs.

## 7. Improve social play

- Make visiting, helping, trading, gifting, and the trade board understandable from both players' perspectives.
- Define limits and feedback for contested actions, failed trades, and inventory changes; verify two-client synchronization.
- **Gate:** gifts and trades cannot transfer value twice when requests are retried; two-player walkthrough passes. **Status:** journal protection added for gifts, gold requests and payments, trade board actions, friend watering, help planting/harvesting, and inspection. Two-farmer integration tests cover duplicate and concurrent retries. CI opens two browser accounts, visits a friend's farm, waters a plot, confirms the owner sees it ready, gifts gold, then completes a trade-board buy request with escrow, inventory transfer, and both balances checked. The trade catalog now has accent-insensitive item search and an escrow preview that explains invalid quantities, missing gold, no matches, and the five-listing limit before submission. Browser checks cover these states and recovery into a completed two-player trade. Sellers now have fillable-first requests, counted availability filters, buyer/item search, and live total proceeds with invalid-quantity handling, covered through the two-player browser transfer. Gold gifting now uses a labeled sheet with recipient, exact amount, remaining-balance preview, invalid-quantity and insufficient-gold guidance, and cancellation. The two-player mobile check verifies rejected amounts, cancellation without value transfer, and a completed transfer with both balances checked. Gold requests now use the same labeled amount sheet with an optional 80-character note and an explicit no-transfer explanation. The two-player walkthrough checks cancellation, request creation without balance changes, and recipient payment with both balances verified. The request inbox and history now use readable cards with exact payment amounts, remaining balances, shortfall guidance, and recipient-specific confirmation. Mobile checks cover unaffordable requests, refusal, and cancelled payment confirmation without transferring value. A three-farmer trade contention check now verifies competing sellers, partial-fill/cancellation races in both submission orders, conservation of gold plus escrow and items, and replay after closing and reopening SQLite; details are in [trade-consistency.md](trade-consistency.md). Broader two-player browser walkthroughs and observed-player validation remain pending.

The recurring festival now has actionable milestone cards, clear progress and reward states, unlock explanations, and a farm prompt for claimable rewards; its [player flow](festival-design.md) is covered by the mobile browser walkthrough. Owned decorations and pets now have a named, collapsible gallery above the field for owners and visitors, with open-state continuity during refreshes. The gallery is height-bounded and keyboard-scrollable; the mobile walkthrough checks every catalog decoration and pet in owner, shop, and visitor views. The personalization shop now has full-width cards with price and shortfall guidance, counted ownership/affordability filters, and browser coverage of title purchase, activation, removal, and reapplication. Observed-player validation remains pending.

- **Ready reward hub:** the farm groups claimable daily chests, next star milestones, collections, and festival rewards with links to their claim screens. Mobile coverage follows daily and star claims and checks that claimed entries disappear.

- **Star milestone decisions:** the next claim and missing-star summary now appear above readable progress/reward cards. Named progress bars and claimed/ready/locked states explain sequential rewards, with direct quest and unlocked-order shortcuts. Mobile coverage verifies a ready claim, next-milestone progress, both activity routes, accessibility, and layout.

## 9. Harden the backend and data model

- Finish replay protection for every value-changing endpoint; keep each mutation and its result in one SQLite transaction.
- Validate request bodies, enforce consistent error responses, review auth/CSRF boundaries, and add safe migrations and backup instructions.
- Add request IDs and operational metrics for error rate, latency, cold starts, and replayed mutations.
- **Gate:** mutation integration tests cover duplicate requests, concurrent requests, and restarts; migration works on a copy of production data. **Status:** journal foundation and fifty-nine routes covered, including upgrades, fishing, fish farming, gem and energy purchases, luxury purchases/equipment, collection claims, watering, inspection, help planting/harvesting, gold requests, speedups, skills, dog hiring, fruit-tree changes, timed critter rewards, away-report dismissal, and crop/barn/machine theft. Purchase, queue, and fish-harvest endpoints reject malformed quantities and IDs; integration tests verify unchanged player value and valid bulk actions. All API mutations require JSON and reject cross-site browser requests before farmer state changes; direct and HTTPS-proxy origin tests pass. Schema upgrades run in one transaction; tests cover preservation of a running legacy machine job, idempotent reopen, and rollback on forced failure. A [backup and rehearsal command](operations.md) restores and migrates a temporary copy, verifies integrity and core row counts, and boots the game API to request an existing farmer's state; a synthetic-data CLI test checks the source remains unchanged and backups cannot be overwritten. API responses carry request IDs, and a secret-protected metrics endpoint exposes startup readiness, uptime, request/error counts, latency buckets, and mutation replays. Persistent monitoring, external request cold-start timing, production-data migration rehearsal, staging restore rehearsal, and remaining route-level tests are pending.

- **Client response ordering:** successful journaled mutations now increment a persisted per-farmer mutation version. The client ignores an older mutation response and refreshes; independent plots can be pending at the same time. A browser race check delays the first planting response, completes a second planting, then verifies the older response does not roll back gold or plots. Other mutation resources still use the shared lock.
- **Retry payload compatibility:** new mutation records hash a canonical JSON body, so retries with the same fields in a different order replay. Existing records retain their original hash and still replay when sent in their original order; the purchase integration test covers both formats and checks that value moves once.
- **Animal action validation:** feed and collect reject unknown or malformed animal kinds before touching inventory or animal readiness; omitting the kind still selects chickens for the legacy shortcut. Integration coverage checks both behaviors and replay safety.
- **Catalog ID validation:** animal purchase/upgrade, machine queue/collect/upgrade/speedup, and fish stocking accept only own catalog IDs. Integration checks prototype-like IDs return `bad_request` without changing gold, inventory, queues, animals, fish batches, or upgrade levels.
- **Crop and tree ID validation:** individual and bulk planting, tree planting, and shared item lookup now exclude inherited object names. Integration checks malformed crop/tree IDs return `bad_request` without changing gold, XP, mutation version, or plots.
- **Purchase catalog validation:** luxury purchases and skill learning also reject inherited object names. The integration snapshot includes sunk gold, skill ranks, equipped cosmetics, and luxury ownership when checking rejected requests.
- **Mutation target contract:** JSON object bodies, numeric target IDs, plot indexes, catalog-key strings, and harvest-help modes are checked before farmer state loads. Explicit malformed watering owners no longer select the caller's farm. The [input contract](api-inputs.md) and two-farmer integration test cover rejected targets with unchanged value and valid watering shortcuts.
- **Sheet continuity:** a completed plot action closes only the sheet from which it began. A second browser race check holds a planting response while the player opens another seed chooser, then verifies that chooser remains usable.

- **Concurrent planting and animal spending:** these routes now read current farmer state inside the journal transaction. A deterministic two-request barrier test covers separate plots sharing one seed budget, the two chicken purchase routes sharing one animal budget, and mixed planting/bulk-animal purchases. It verifies one winner, exact debit and ownership, and unchanged winning retries; details are in [spending-consistency.md](spending-consistency.md).

- **Shared capacity contention:** the same deterministic barrier now covers the generic and legacy chicken-barn upgrade routes sharing one upgrade budget, plus single/max fish stocking competing for the final pond slot. It verifies one winner, exact debit, the resulting barn level or total pond occupancy, and unchanged winning retries.

- Measure mobile startup, image payload, rendering work, and state polling. Optimize the measured bottlenecks.
- Audit keyboard control, focus after sheets close, text contrast, screen-reader names, touch size, and reduced motion.

Automated WCAG A/AA scans of the 320px farm, seed chooser, inventory, order sheet, trade board, and desktop shop report zero violations and are enforced in CI; this caught missing quantity and trade-form labels, low order-text contrast, conflicting button names, and disabled pinch zoom. The trade form now has visible labels and 44px controls. The [mobile transfer baseline](performance-baseline.md) shows first-load image transfer falling from 1.69 MB to 0.76 MB after the first scene resize; the new matched building trio brings the current sample to 0.78 MB, within enforced image and total-local transfer budgets. Farm sheets, leaderboard, and return report have dialog semantics, keyboard focus traps, Escape handling, and focus return. Factory recipe controls have 44px minimum touch targets, visible keyboard focus, action-specific screen-reader names, and distinct full-queue and missing-ingredient messages. Missing ingredients now appear on the recipe card with their quantities, and a clear shopping-cart action opens the existing buy-request confirmation. The twelve machine icon exports total 424,085 bytes, down from 1,266,201 bytes. Growing crop and tree accessible names now update with their visible countdowns; the mobile walkthrough waits for a timer tick and checks their consistency. Manual keyboard/screen-reader and performance audits remain pending.

- Merge the tested branch into `master`, publish release notes, and monitor first-session and day-2 results.

## 12. Iterate from actual player behavior

- Keep the asset inventory, balance model, tests, and this roadmap updated as gameplay changes.
- **Gate:** next release priorities are chosen from player evidence, not only code inspection. **Status:** pending staged release.
